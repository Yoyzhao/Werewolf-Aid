**冻结**

- `SETTLE` 为引擎内部过渡阶段；UI 在胜负成立后直接进入 `result`，不单独展示“结算中”页面。
- 视图切换不要求独立 URL；刷新恢复依赖本地存储（见第 8 节）。
- 底部 Tab 仅 `home`、`assistant`、`rules` 显示；对局中隐藏，由底部操作坞接管。
- PC ≥1024px：主持相关页面双栏（主内容 + 右侧座位/事件栏）；不显示底部 Tab。

### 2.2 流程条映射（已模拟验证）

| 当前页 | 一阶高亮 | 一阶已完成 | 二阶子步骤 |
| --- | --- | --- | --- |
| `setup` | 设置 | 无 | 隐藏 |
| `deal` | 发牌 | 设置 | 隐藏 |
| `night` | 夜晚 | 设置、发牌 | 隐藏 |
| `sheriff` | 白天 | 设置、发牌、夜晚 | 首日且开启竞选：第 1 步“竞选” |
| `dawn` | 白天 | 同上 | 首日且开启竞选：第 2 步“死讯”；否则第 1 步 |
| `speech` | 白天 | 同上 | 首日且开启竞选：第 3 步“发言”；否则第 2 步 |
| `vote` | 白天 | 同上 | 首日且开启竞选：第 4 步“投票”；否则第 3 步 |
| `result` | 结算 | 设置、发牌、夜晚、白天 | 隐藏 |
| `home`/`assistant`/`rules` | 隐藏 | 不适用 | 隐藏 |

- 首日且开启警长竞选：子步骤为「竞选 → 死讯 → 发言 → 投票」。
- 关闭首日竞选或第 2 天起：子步骤收缩为「死讯 → 发言 → 投票」，序号重排。
- 流程条只读，不允许点击跳步。

### 2.3 刷新与恢复

- 应用启动读取本地对局：存在 `status=active` 的对局时，首页显示“继续上一局 / 放弃并清空”恢复卡。
- 存在 `status=finished` 的对局时，首页显示“查看上一局结果”，进入只读结算页，不重新结算。
- 继续：恢复到最近一次落库的 `phase`、`round`、`nightStep`、`view`；`view` 按 8.3 映射校验，非法则回退到阶段入口页。
- 恢复时关闭遮罩、核对、弹窗、抽屉等浮层，不恢复输入焦点。
- 放弃：二次确认后清除对局存储，保留助手记录与 AI 配置。
- 数据版本不兼容：提示“本地对局数据版本不兼容，需要重新开局”，不允许静默加载。

## 5. 关键交互与守卫

### 5.1 开局设置

- 板子二选一（预女猎守/预女猎白）；切换板子后角色构成条同步。
- P0 座位固定 1–12，不提供增删；只校验持久化数据完整性（缺号/重号/越界）。
- 发牌模式 A/B/C 必选其一，默认 A；模式说明随选择切换。
- 设置项：首夜警长竞选（默认开）、女巫首夜自救（默认开）。
- “开始发牌”二次确认；确认后清空上一局对局状态，保留助手记录与 AI 配置。
- 进入发牌前请求 Wake Lock；不支持或失败时提示一次（见 8.5）。

### 5.2 发牌

**共同守卫**

- 12 人全部完成才可进入夜晚；“完成发牌，进入天黑”防连点。
- 已发座位不可重复；回退仅撤销最近一步且需确认。
- 发牌完成后写入本地存储；P1 在此时写入首个快照（下一迭代）。

**A 接力查看**

- 全屏遮罩显示“请把手机交给 X 号，其他人请勿观看”。
- 玩家点“查看我的身份”才显示；点“我已记住，交给下一位”回遮罩并推进。
- 非当前玩家不得看到身份；遮罩期间不渲染身份内容。

**B 线下逐步确认**

- 默认遮罩“请 X 号确认身份”；主持人点“显示身份”为二次揭示。
- 揭示后点“X 号已确认”推进；可重新遮罩。
- 私密信息暴露面不高于 A；不允许默认直接显示身份。

**C 实体牌录入**

- 玩家全程不看屏；主持人按实体牌录入。
- 只显示当前号与角色池；角色余量为 0 禁用；已选明细默认隐藏。
- “撤销上一位”仅在已录 >0 时可用，撤销后回到上一位。
- “核对已录（防窥）”必须二次确认；确认后显示 1–12 映射，退出即恢复隐藏。
- 12 人未满或角色构成与板子不一致：禁止进入夜晚并提示。
- 系统不生成、不揭示身份；后续流程使用录入映射。

### 5.3 夜间

- 顺序固定：预女猎守「守卫 → 预言家 → 狼人 → 女巫」；预女猎白「预言家 → 狼人 → 女巫」。
- 每步必须选择目标或显式“空守/空刀/不用药”才可下一步。
- 守卫：不可连守同一目标（跨夜校验）；可自守；不防毒；界面显示上一夜守护对象。
- 狼人：P0 只录入一个共识目标；意见不一致按空刀（主持人执行）；可空刀/自刀；主持端显示狼队名单。
- 预言家：选择目标后，主持端显示“X 号是好人/狼人”的阵营结果；该结果仅主持端可见。
- 女巫：解药仅救当夜被刀者；空刀不可解药；首夜自救受设置控制；同夜不可两瓶；同守同救目标死亡；显示剩余药瓶。
- 私密信息：刀口、查验结果、狼队、用药仅主持端展示；不得写入公开事件。
- 夜晚结束计算死亡/平安夜，写入公开事件后进入 `CHECK_WIN`；未结束再进入竞选或死讯。

### 5.4 白天

**警长竞选（首日）**

- 数据：`candidates[]`、`withdrawn[]`、`candidateSpeech[]`、`ballots[]`、`pkCandidates[]`、`elected`。
- 阶段：报名 → 竞选发言（可打卡）→ 退水 → 警下投票 → 平票 PK → 当选/流失。
- 首夜死者不参与；上警玩家可多选；支持“本局无警长”。
- 警上玩家无投票权；只有存活且未退水、未上警的玩家参与警下投票。
- 平票进入 PK 复投，仅平票候选人可被投；再平则本局无警长。
- 竞选自爆吞警徽；自爆入口在竞选页，确认后进入 `SELF_EXPLODE` 并立即检查胜负。

**死讯/遗言/技能**

- 平安夜与出局名单二选一；出局显示死因（被刀/被毒/同守同救）。
- 遗言资格：首夜死亡、白天出局有遗言；第 2 夜及以后夜晚死亡无遗言；自爆默认无遗言。
- 遗言列表显示符合资格的座位，标记“待发言/已发言/跳过”，不阻塞进入发言。
- 猎人被刀在此开枪：选择存活目标或跳过；被毒/被白狼王带走不可开枪。
- 警长死亡处理警徽：选择存活目标移交或撕毁；需要二次确认。
- 所有技能结算后进入 `CHECK_WIN`，再进入发言。

**发言**

- 默认顺序：从首名死者下一位开始顺时针；无死亡从 1 号开始；警长可指定起始座位。
- 列表可点选标记“已发言”，仅作主持辅助，不阻塞进入投票。
- 自爆随时可打断：确认 → 白狼王带人（如适用）→ 警徽处理（如竞选）→ `CHECK_WIN` → 入夜/结算。

**投票**

- 数据模型：`ballots: { voter, target, weight }[]`；`target=null` 表示弃票；`weight` 由系统计算（警长存活且投票时为 1.5，其余为 1）。
- 放逐投票选民：存活玩家；白痴翻牌后无票；警长竞选阶段的警上玩家无票（仅竞选投票）。
- 录入方式：
  - **逐票录入**：按选民顺序选择目标或弃票，每个选民一票，可修改。
  - **快速归票**：把未录入选民一次性归给当前选中目标，仍生成逐票记录。
- 统计：按目标累加权重；显示 0.5 精度（如 `3.5 票`）；弃票不计入最高票。
- 平票：进入 PK 复投，清空上一轮票并只允许投平票候选人；再平本轮无人出局。
- 白痴被放逐：翻牌免死、保留发言、失去投票权、不再成为放逐目标。
- 放逐后依次处理白痴翻牌、猎人开枪、警徽流转，然后 `CHECK_WIN`；未结束进入下一夜。
- “放逐并检查胜负”为二次确认动作；未产生胜利则进入下一夜。

### 5.5 技能、自爆与二次确认

| 技能/动作 | 触发 | 目标选择 | 守卫 | 结果 |
| --- | --- | --- | --- | --- |
| 猎人开枪（DAWN） | 猎人被狼刀 | 存活玩家或跳过 | 被毒/被白狼王带走不可 | 目标出局；立即 `CHECK_WIN` |
| 猎人开枪（SETTLE） | 猎人被放逐 | 存活玩家或跳过 | 同上 | 目标出局；立即 `CHECK_WIN` |
| 警徽移交 | 警长死亡 | 存活玩家 | 不可移交自己 | 目标成为警长 |
| 撕毁警徽 | 警长死亡 | 无 | 二次确认 | 本局无警长 |
| 白狼王带人 | 白狼王自爆 | 存活玩家 | 最后一狼自爆不带人 | 目标出局；`CHECK_WIN` |
| 白痴翻牌 | 白痴被放逐 | 无 | 自动 | 免死、失去投票权、不再成为目标 |
| 自爆 | 竞选/发言 | 无 | 二次确认 | 中止流程；警徽处理；`CHECK_WIN` |

| 操作 | 快照 | 二次确认 | 结算后可回退 |
| --- | --- | --- | --- |
| 发牌完成 | 是 | 是 | 否 |
| 夜间每步确认 | 是 | 否 | 否 |
| 竞选各阶段 | 是 | 自爆 | 否 |
| 死讯/遗言/技能 | 是 | 开枪/警徽/带人 | 否 |
| 放逐/投票提交 | 是 | 是 | 否 |
| 自爆 | 是 | 是 | 否 |
| 清空/再来一局 | 否 | 是 | 是（清空） |

- 回退保留最近 30 个快照；回退后同步重写本地存储，不产生重复事件。
- 纯 UI 状态（遮罩、发言打卡、防窥核对、输入焦点）不进入快照。

## 6. 前端状态机

| 当前 | 事件 | 守卫 | 下一 | 副作用 |
| --- | --- | --- | --- | --- |
| SETUP | START_DEAL | 板子/模式有效；模式 C 已确认实体牌 | DEAL | 清空上一局；准备身份映射；请求 Wake Lock；落库 |
| DEAL | DEAL_DONE | 12/12；模式 C 构成一致 | NIGHT | 记录映射；落库；进入第 1 夜 |
| NIGHT | NIGHT_STEP_NEXT | 当前步已选目标或空操作 | NIGHT | 记录动作；落库 |
| NIGHT | NIGHT_DONE | 最后一步完成 | CHECK_WIN | 计算死亡/平安夜；写公开事件；落库 |
| SHERIFF | SHERIFF_DONE | 已当选或无警长 | DAWN | 记录警长；落库 |
| SHERIFF | SELF_EXPLODE | 竞选阶段允许 | SELF_EXPLODE | 中止竞选；吞警徽；落库 |
| DAWN | DAWN_DONE | 死讯、遗言、技能处理完成 | CHECK_WIN | 写公开事件；落库 |
| SPEECH | SPEECH_DONE | 无 | VOTE | 落库 |
| SPEECH | SELF_EXPLODE | 发言阶段允许 | SELF_EXPLODE | 中止发言；落库 |
| SELF_EXPLODE | EXPLODE_RESOLVED | 白狼王带人、警徽处理完成 | CHECK_WIN | 写事件；落库 |
| VOTE | VOTE_DONE | 投票完成且无平票 | SETTLE | 放逐；落库 |
| VOTE | VOTE_PK | 平票 | VOTE | 清空票；仅平票候选人可投 |
| SETTLE | SETTLE_DONE | 白痴/猎人/警徽结算完成 | CHECK_WIN | 落库 |
| CHECK_WIN | WIN | 满足屠边 | RESULT | 停止 Wake Lock；落库只读结果 |
| CHECK_WIN | NO_WIN | 未满足 | 返回 `resumeTo`（SHERIFF/DAWN/SPEECH/NIGHT） | 落库 |
| RESULT | AGAIN | 无 | SETUP | 保留编号；删除对局快照 |
| RESULT | WIPE | 确认 | HOME | 删除对局快照；释放 Wake Lock |
| 任意 | BACK | 有快照且非 RESULT | 上一状态 | 恢复快照；重写存储 |

- `CHECK_WIN` 的 `resumeTo` 由进入时记录；夜间死亡、DAWN 技能、SETTLE 技能、自爆后都必须检查。
- 非法事件返回 `INVALID_STATE`（引擎层），UI 只提示不改变状态。
- 每步先落库成功再推进 UI；落库失败仍可继续，但显示常驻警告。

## 7. AI 配置、上下文与状态机

### 7.1 配置

| 字段 | 必填 | 规则 | 保存位置 |
| --- | --- | --- | --- |
| 接口地址 | 是 | 仅 https；完整 URL；服务端再做 SSRF 校验 | IndexedDB `meta` |
| 模型名 | 是 | 非空；作为 `model` 传入 | IndexedDB `meta` |
| API Key | 是 | 密码输入；默认只存内存；可勾选“记住本次会话”存 sessionStorage | 内存/sessionStorage |
| 记住本次会话 | 否 | 默认关闭；关闭标签页即失效；不写 localStorage/IndexedDB | 内存标记 |
| 温度 | 否 | 0–2，默认 0.7 | IndexedDB `meta` |
| 最大输出 | 否 | 100–2000，默认 800 | IndexedDB `meta` |

- 操作：“保存配置”“清除配置”“显示/隐藏 Key”。
- 保存只做格式校验，不发起网络请求；首次分析请求由服务端验证。
- P0 不提供长期记住 Key；ADR-004 的可选“记住”延后，作为 5B 决策记录。
- 配置缺失时 AI 面板显示 `config-missing`，主持/助手/规则不受影响。

### 7.2 上下文预览

- 分段展示：我的身份、当前局势（轮次/存活/公开事件）、玩家标签、信息记录、发言要点、自由描述。
- 自由描述可编辑，≤2000 字；预览总长 ≤20000 字；超出时提示并截断发送。
- 预览中不出现 Key；显示“上下文将发往你自配的第三方模型”的固定提示。
- 用户可折叠任一分段；发送前不写日志、不落库。
- AC-8 要求标签/信息/要点被组装进预览；AC-9 要求输出三段以上并标注依据。

### 7.3 状态机

| 状态 | 触发 | UI | 退出 |
| --- | --- | --- | --- |
| `config-missing` | 未配置地址/模型/Key | 配置引导 + 隐私提示 | 保存配置 → idle |
| `idle` | 已配置但未请求 | 空态 + “让军师整理” + 上下文预览 | 点击请求 → loading |
| `loading` | 发起请求 | 加载文案 + 取消；按钮禁用 | 成功/失败/取消/60s 超时 |
| `success` | 200 且内容有效 | 三段以上 + 依据 + 边界提示 | 再次请求 → loading |
| `error` | 业务错误/网络/超时 | 错误文案 + 重试 | 重试 → loading |
| `cancelled` | 用户取消 | “已取消，未产生结果” | 再次请求 → loading |

- 单会话同时最多 1 个在途请求；取消使用 `AbortController`。
- 超时 60s；UI 在超时后 2s 内给出提示；不自动重试。
- 输出按纯文本/安全 Markdown 渲染，禁止内联 HTML。
- 5A/5B 原型为演示保留样例结果；5C 首次进入显示 `idle` 空态，不展示虚构分析内容。

| --- | --- | --- |
| `KEY_INVALID` | Key 无效，请检查后重试 | 是 |
| `QUOTA` | 额度不足，请检查账户余额 | 是 |
| `TIMEOUT` | 请求超时（60 秒），请稍后重试 | 是 |
| `NETWORK` | 网络不可用，请检查网络后重试 | 是 |

| `UPSTREAM_4XX` | 模型服务拒绝了请求，请检查模型配置 | 是 |
| `UPSTREAM_5XX` | 模型服务暂时不可用，请稍后重试 | 是 |
| `INVALID_REQUEST` | 请求参数有误，请检查模型配置 | 否 |

## 8. 本地存储与恢复

### 8.1 存储划分

| 存储 | 键/对象 | 内容 | 生命周期 |
| --- | --- | --- | --- |
| IndexedDB `werewolf-aid` v1 | `game` / `current` | 对局状态、事件、快照栈、只读结果 | 再来一局/清除后删除 |
| IndexedDB `werewolf-aid` v1 | `assistant` / `current` | 身份、标签、信息、发言要点、局势 | 手动清空 |
| IndexedDB `werewolf-aid` v1 | `meta` / `settings` | 默认板子、AI 地址/模型/温度/最大输出 | 长期 |
| sessionStorage | `lrs.ai.key.v1` | 勾选“记住本次会话”时的 Key | 关闭标签页失效 |
| localStorage | `lrs.guide.v1` | 首次引导已读标记 | 长期 |
| 内存 | AI Key | 未勾选记住时仅本次会话 | 刷新即失效 |

- 不把 Key、AI 上下文全文、玩家笔记写入日志。
- 版本字段 `schemaVersion=1`；升级时迁移或提示不兼容。

### 8.2 写入时机与失败

- 对局：开局、发牌完成、每步夜间确认、竞选各阶段、死讯/遗言、技能结算、投票提交、结算、回退后各写一次。
- 结算：写入 `status=finished` 的只读结果快照，保留至“再来一局/清除本局”；刷新可查看，不重新结算。
- 助手：文本输入去抖 300ms 写入；标签点击立即写入。
- 写入失败：不阻塞操作；顶部显示常驻条“本机保存失败，刷新可能丢失。请勿关闭页面。”并提供重试。
- 清理浏览器数据会导致本地记录丢失；首次引导与设置页明确提示。

### 8.3 恢复映射

| 落库 phase | 恢复 view | 说明 |

| SETUP | `setup` | 保留设置项 |
| DEAL | `deal` | 关闭遮罩，回到当前号 |
| NIGHT | `night` | 回到当前 `nightStep` |

### 8.5 Wake Lock

- 进入发牌时请求；页面重新可见且处于对局中时重新请求。

- 不支持或请求失败：提示一次“未能开启屏幕常亮，请在系统设置中关闭自动锁屏”，不重复打扰。

## 10. 移动端与可访问性

- 主设计 360px；支持 320–440px；≥720px 内容加宽；≥1024px 主持双栏。
- 触控目标 ≥44×44px；间距 ≥8px；不依赖 hover。
- 视口 `100dvh`；底部操作坞与 Tab 适配 `env(safe-area-inset-bottom)`。
- 输入框字号 ≥16px；键盘弹出时操作坞上移，不遮挡输入。
- 对局内顶栏固定一阶流程条；白天再加二阶子步骤，合计高度 ≤64px。
- 焦点可见：`focus-visible` 使用金色描边；对话框焦点陷阱并可 Esc 关闭。
- 对比度 ≥4.5:1；正文不小于 12px；支持系统字体放大不截断。
- 尊重 `prefers-reduced-motion`：关闭入场、旋转、雾气漂移与按钮高光动画。
- 骨架/加载不阻塞操作；任何异步操作 ≤100ms 给出可见反馈。
- 性能预算（AC-17）：首屏 JS ≤250KB gzip；5G/Wi-Fi 首屏 ≤2s、可交互 ≤3s；4G ≤3s/≤5s；点击反馈 ≤100ms；主流 60fps、中端 ≥55fps；长任务 ≤50ms。

## 11. API 契约对齐（P0）

| 场景 | 契约 | UI 行为 |
| --- | --- | --- |
| 应用启动 | `GET /api/v1/session` | 取 `csrfToken` 存内存；失败不阻塞本地主持，仅 AI 不可用 |
| CSRF 失效 | 401/CSRF 错误 | 重新 `GET /session` 一次并重试原请求；再失败提示 |
| AI 请求 | `POST /api/v1/ai/relay` | 按第 7 节状态机；取消用 AbortController |
| 健康检查 | `GET /api/v1/health` | 运维使用，不进入 UI |
| P1 房间 | `/api/v1/rooms/*` | 仅引用，不在 5C/5D P0 实现 |

- AI 请求体上限 128KB、响应 1MB、连接 30s、总 60s；超限按错误处理。
- 错误格式统一 `{ error: { code, message, details } }`；UI 只使用 `code` 映射文案。
- Key 不进入 URL、日志、错误上报；仅 HTTPS。
- 离线：已加载页面可继续主持；AI 显示网络错误，不阻塞其他功能。
- P1 快照/视图/WS 契约以 [api-contract.md](api-contract.md) 第 3 节为准，本轮不实现。
