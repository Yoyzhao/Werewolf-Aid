# ADR-005 部署与运行形态

- 编号：ADR-005
- 状态：已接受（2026-11-25 用户确认：不使用 Nginx/Docker）
- 日期：2026-11-25
- 关联：PRD v1.3.1；ADR-001/002/003

## 背景

目标为单服务器部署：P0 只需要静态前端 + AI 中转；P1 增加 WebSocket 与 SQLite。用户 2026-11-25 明确暂不使用 Nginx 和 Docker；Node 环境已更新至 24.22.3。

## 决策

- **拓扑**：浏览器 → HTTPS → **Node/Fastify 单进程**：
  - `@fastify/static` 提供 `apps/web/dist` 静态资源与 SPA fallback；
  - Fastify 提供 `/api/*`；
  - P1 Socket.IO 挂载同一 HTTP/HTTPS server，提供 `/ws/*`。
- **TLS**：Node HTTPS 直接终止；证书用 DNS-01/webroot（避免 certbot standalone 占用 80 与 Node 冲突），或云证书；443 绑定用 systemd `CAP_NET_BIND_SERVICE` 或云 LB 回源 3000。保持 HTTP/1.1 以兼容 Socket.IO。不使用 Nginx。
- **进程**：systemd 或 PM2 守护单实例；HTTP 80 跳转 HTTPS（或由云 LB 处理）。
- **静态/安全**：`@fastify/static` + `@fastify/compress` + `@fastify/helmet`；哈希资源长缓存、`index.html` 不缓存；`/api`、`/socket.io` 先注册，SPA fallback 只处理非 API GET。
- **请求限制**：Fastify `bodyLimit`、`requestTimeout`（≥AI 60s）、`headersTimeout`、`connectionTimeout`、`keepAliveTimeout`；WS `maxHttpBufferSize`；AI 每会话 1 个在途 + 全局并发上限。云 LB 场景配置 `TRUST_PROXY`。
- **容器**：不使用 Docker；未来需要隔离/多实例时再评估。
- **数据库**：P1 SQLite 文件持久目录；WAL；备份/恢复。

## 适用范围

- v1.3.1 P0 与 P1 预留部署。
- 不决定云厂商、域名与证书供应商。

## 后果

- 部署更简单：一个 Node 进程、一个端口、一个构建产物；无需维护反向代理。
- Node 需要承担 TLS、静态、压缩、安全头、限频与 WebSocket；证书续期和 443 端口权限需要运维。
- 单进程同时服务静态/API/WS；流量增长时可能需要云 LB/CDN 或拆分。
- 无反向代理层缓存；静态资源依赖 Fastify 缓存头与浏览器缓存。
- 不使用 Docker，环境依赖直接落在服务器；需记录 Node 版本与启动命令。

## 替代方案

- **Nginx**：成熟的反代/TLS/缓存，但用户暂不使用；未来可作为 TLS 卸载/缓存层再评估。
- **Docker Compose**：隔离更好，但用户暂不使用；未来可评估。
- **云负载均衡/CDN**：可替代 Nginx 做 TLS 终止与静态加速；不引入 Nginx/Docker，作为可选方案。
- **Serverless**：WebSocket/长连接与 SQLite 不适配。

## 验证方式

- HTTPS 访问、HTTP→HTTPS 跳转、HSTS/安全头。
- 静态 SPA 路由 fallback、哈希资源缓存、gzip/brotli；API/WS 路由不被静态吞掉。
- API 与 P1 WebSocket 同源可用；健康检查 `/api/v1/health`。
- 大包/慢请求/超时/WS 超限；AI 并发上限；证书续期演练；SQLite 备份/恢复；静态/后端回滚。
- 移动端真机访问与 Lighthouse。

## 重评触发

- 需要 TLS 卸载、静态缓存、限流前置或反向代理能力 → 云 LB/CDN 或 Nginx（另行确认）。
- 需要多实例/容器化 → 容器平台 + PostgreSQL + Redis adapter。
- 用户恢复使用 Nginx/Docker。
