# ADR-002 数据存储与持久化

- 编号：ADR-002
- 状态：提议（待步骤 3 验收）
- 日期：2026-11-25
- 关联：PRD v1.3.1；ADR-001；ADR-003

## 背景

P0 单机主持与个人助手只需要浏览器本地存储；P1 联机需要服务端保存房间、座位绑定与阶段快照。当前目标是单服务器、试运行 10 个房间、每房 13 人，写入频率为“每阶段一次快照”。

## 决策

- **P0**：不引入服务端业务数据库。使用浏览器 IndexedDB（主）/localStorage（轻量配置）保存对局状态、助手记录、AI 配置与设置；每步落库，刷新可恢复。
- **P1**：使用 **SQLite（WAL）+ Drizzle ORM + better-sqlite3**，单文件数据库，随应用部署；由 API 进程独占写入。步骤 5D 验证 Node 24 预编译；若不可用，再评估 `node:sqlite`。
- **完整状态**：`game_states` 保存主持端写入的完整 `gameState`（含身份/夜间动作），仅服务端访问；`snapshots` 保存服务端生成的公开/私有视图，供玩家读取。
- **AI 中转**：不落库、不写日志；请求在内存中转发。
- **时间**：统一以 UTC epoch 毫秒（INTEGER）存储；展示层按 Asia/Shanghai 格式化。
- **删除**：房间结算/解散时删除 `rooms`、`room_seats`、`game_states`、`snapshots`；另有 TTL 清理过期房间（`expires_at`）。

P1 概念表：

```text
rooms(id PK, code UNIQUE, host_token_hash, board_id, phase, status, version, created_at, expires_at)
room_seats(room_id, seat_no, session_id, status, bound_at, PK(room_id, seat_no), UNIQUE(room_id, session_id))
game_states(room_id PK, version, phase, state_json, updated_at)
snapshots(room_id, version, phase, public_view JSON, private_views JSON, updated_at, PK(room_id, version))
```

索引：`rooms(code)`、`rooms(expires_at)`、`room_seats(room_id)`、`snapshots(room_id, version)`。`game_states.state_json` 只存服务端、不下发玩家；`snapshots` 只存服务端生成的过滤视图；均不存 Key/AI 上下文/玩家笔记。

## 适用范围

- P0 本地存储键与 P1 服务端表结构。
- 不决定物理迁移脚本；迁移在步骤 5D 实现。

## 后果

- 单服务器零数据库运维；备份为 SQLite 文件 + WAL 检查点。
- 备份可能保留已删除房间的短期副本；保留期需与隐私政策一致。
- 不支持多实例并发写；水平扩展前必须迁移到 PostgreSQL。
- 快照按 `version` 递增，旧版本写入被拒绝（与 ADR-003 配合）。
- 服务端持有完整身份/夜间状态；必须限制 DB 访问、不公网、结算删除，并避免日志记录。
- 浏览器存储可能被清理；P0 需提示用户不要清理，并接受“离线冷启动”不作为 P0 承诺。
- `better-sqlite3` 是原生依赖；需验证 Node 24 预编译，否则调整驱动。

## 替代方案

- **PostgreSQL**：并发/HA 更强，但当前规模运维成本高；作为升级路径。
- **仅浏览器存储**：无法支撑 P1 多端共享。
- **Redis 作为主存储**：需额外持久化/恢复策略，不适合作为权威房间数据。

## 验证方式

- SQLite WAL 并发读写测试；迁移 up/down（或前滚）验证。
- 备份/恢复演练：复制数据库文件 + WAL 检查点后恢复。
- 快照版本冲突测试（旧 version 返回 409）；状态非法返回 422。
- 服务端生成视图与 AC-13 越权测试；`game_states` 不出现在玩家接口。
- P0 刷新/重开后 IndexedDB 恢复测试。

## 重评触发

- 需要多实例/容器水平扩展、HA 或复杂查询。
- 并发房间 > 50 或写入频率显著上升。
- SQLite 文件备份/恢复无法满足 RPO/RTO。
