# ADR-001 技术栈与项目拓扑

- 编号：ADR-001
- 状态：提议（待步骤 3 验收）
- 日期：2026-11-24
- 关联：PRD v1.3.1；[技术栈调研](../research/tech-stack-2026.md)

## 背景

项目为移动端优先的 Web 应用：P0 单机主持与个人助手在浏览器本地完成；P1 才需要服务端联机；AI 通过 BYOK + 后端中转。无既有代码，需要一次确定可落地的技术栈与项目拓扑。

## 决策

采用**前后端分离的 TypeScript monorepo**：

| 层 | 选型 |
| --- | --- |
| 前端 | React 19 + Vite + TypeScript；Tailwind CSS + Radix Primitives；Zustand + idb-keyval；React Router |
| 后端 | Node.js 24 + Fastify 5 + TypeScript；Zod 校验 |
| 共享包 | `packages/game-engine`（规则/状态机/胜负）、`packages/shared`（契约/DTO/错误码）、`packages/rules-content`（板子/角色/流程） |
| 数据库 | P0 无服务端持久化；P1 SQLite（WAL）+ Drizzle ORM |
| 实时 | P1 Socket.IO（WebSocket），轮询降级 |
| 包管理 | npm workspaces（npm 11 已安装；不引入 pnpm 前置） |
| 测试 | Vitest + React Testing Library + Playwright；后端 Fastify inject |
| 部署 | Node 单进程（Fastify static/API/WS）；无 Nginx/Docker；TLS 由 Node HTTPS 或云 LB |

目录：

```text
apps/web
apps/api
packages/game-engine
packages/shared
packages/rules-content
docs/
```

## 适用范围

- 覆盖 v1.3.1 P0 全部功能与 P1 预留架构。
- 不改变 PRD 的产品范围与验收标准。

## 后果

- 规则引擎同时服务浏览器与 API，避免规则口径重复。
- 前端/后端可独立构建与测试；共享包通过 TypeScript 类型与 Zod 契约对齐。
- 需要维护 monorepo 构建顺序与共享包版本。
- 不采用 SSR；首屏依赖静态资源与本地缓存，符合 P0 本地优先。
- Node 24 与 Fastify 5 的兼容性需首次安装时验证。

## 替代方案

- **Vue 3 + Vite**：可行，但与已确认的推荐方案不一致，需重新对齐。
- **Next.js/Nuxt 全栈**：不需要 SSR；WebSocket 常需额外服务，P0 本地优先收益低。
- **Python FastAPI**：双语言会重复规则/契约定义。
- **NestJS**：对当前规模偏重。

## 验证方式

- `npm install` 后构建 web/api，确认 Node 24 兼容。
- `packages/game-engine` 单测覆盖附录 A 规则用例。
- 前端 Lighthouse 移动端与首屏 JS 预算（≤250KB gzip）。
- API Fastify inject 集成测试。

## 重评触发

- 需要 SSR/SEO 或团队明确要求 Vue。
- 首屏包体持续超出预算且无法通过拆分解决。
- 需要多实例部署或独立扩缩容。
