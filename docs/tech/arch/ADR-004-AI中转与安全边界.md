# ADR-004 AI 中转与安全边界

- 编号：ADR-004
- 状态：提议（待步骤 3 验收）
- 日期：2026-11-24
- 关联：PRD v1.3.1；ADR-001

## 背景

AI 采用 BYOK：玩家自配 URL / Key / 模型名。浏览器直连第三方端点会暴露 Key、受 CORS/混合内容限制，也无法统一做 SSRF 与限频；因此需要后端中转。

## 决策

- 前端组装上下文 → `POST /api/v1/ai/relay` → 后端向玩家配置的 Chat Completions 端点发起 HTTPS 请求 → 返回内容。
- **Key 不落库、不写日志、不进入错误上报**；默认只保存在内存/会话存储，可选“记住”默认关闭。
- **SSRF 防护**：仅 https；解析域名后拒绝私网/环回/链路本地/元数据地址；不跟随到私网的重定向；连接 30s、总 60s；响应 ≤1MB。
- **限频**：按会话/IP 限频（示例 10 次/分钟，具体值步骤 5D 定）。
- **输出安全**：AI 输出按纯文本/安全 Markdown 渲染；禁止内联 HTML；CSP 限制脚本源。
- **失败降级**：超时/额度/无效 Key 给出错误码与友好文案，不阻断主持/助手/规则查阅。

## 适用范围

- P0 AI 辅助；P1 联机不改变该链路。
- 不内置默认模型、不代管 Key。

## 后果

- 后端成为 AI 请求的唯一出口，便于审计/限频/SSRF 防护。
- 单点故障会影响 AI，但不影响 P0 本地主持。
- 第三方模型的内容责任仍由玩家/服务方承担，需在 UI 与隐私政策中提示。
- 流式输出暂不支持；如后续需要，另评估 SSE/流式代理。

## 替代方案

- **浏览器直连**：Key 暴露、CORS/合法域名/混合内容限制，不可行。
- **边缘函数**：可做，但引入平台锁定与额外部署面；当前单服务器不需要。
- **平台默认 AI 通道**：P2 规划，当前不内置。

## 验证方式

- SSRF 用例：私网、回环、元数据、重定向到私网、非 https。
- 超时/响应过大/限频/无效 Key 的错误码测试。
- 日志与数据库检查：无 Key、无上下文全文。
- 输出 XSS 用例：恶意 Markdown/HTML 不执行。

## 重评触发

- 平台提供合规的统一 AI 代理，且成本/体验更优。
- 需要流式输出或多模态。
- 真实供应商的错误码/超时行为与假设不符。
