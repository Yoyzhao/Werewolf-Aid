# ADR-003 联机同步与匿名身份

- 编号：ADR-003
- 状态：提议（待步骤 3 验收）
- 日期：2026-11-25
- 关联：PRD v1.3.1；ADR-002

## 背景

P1 联机需要 12 名玩家 + 1 名主持人同步阶段与私密信息，但不建账号体系。主持人是唯一写入者，玩家只读自己的视图；必须避免客户端拿到原始全局状态。

## 决策

- **身份**：匿名会话 Cookie（`httpOnly + Secure + SameSite=Lax`）+ 房间令牌；不做账号。
- **主持人**：创建房间时生成随机主持人令牌（至少 32 字节），只返回一次；服务端只存 SHA-256 哈希。可选恢复码用于换设备。
- **玩家**：会话 + 配对码 + 编号申请，主持人确认后绑定；一个编号只能绑定一个会话。
- **同步**：P1 用 **Socket.IO** 推送；服务端为房间状态的存储与分发方，主持端是唯一写入者。WebSocket 不可用时降级 5s 轮询 `GET /view`。
- **快照**：主持端每阶段写入带 `version` 的**完整 `gameState`**；服务端用同一 `game-engine` 校验状态并生成公开/私有视图。服务端拒绝旧版本（409 `STALE_VERSION`）与非法状态（422 `INVALID_STATE`），玩家端只接收递增版本。
- **过滤**：服务端按角色生成视图；完整 `gameState` 只存服务端，不下发玩家端；主持端不发送现成 `privateViews`。前端遮罩只作辅助，不作为保密依据。
- **写路径**：主持端通过 HTTP 写完整 `gameState`；WebSocket 只做服务端→客户端的视图推送，不承载主持写操作。

## 适用范围

- P1 联机（下一迭代）；P0 单机不使用服务端房间。
- 不改变 P0 的本地主持流程。

## 后果

- 单实例 Socket.IO；水平扩展需要粘性会话或 Redis adapter。
- 主持人令牌遗失需重建房间；恢复码是可选缓解。
- 服务端必须运行与前端相同的规则引擎做状态校验，并由服务端生成视图；服务端持有完整身份/夜间状态，需限制 DB 访问、不公网、结算删除。
- 匿名会话跨浏览器不同步；加入页提示“同一浏览器完成绑定”。
- `SESSION_SECRET` 轮换会使所有匿名会话/房间绑定失效；需公告/维护窗口；主持令牌独立，恢复码仍可用。

## 替代方案

- **原生 WebSocket**：更轻，但重连/房间/降级需自写。
- **SSE + HTTP**：单向推送可用，但写操作仍需 HTTP，连接管理弱。
- **纯轮询**：实现最简单，延迟与请求量较高；保留为降级。
- **账号体系**：能解决跨设备，但增加注册/隐私/合规成本，超出当前范围。

## 验证方式

- 主持人/玩家越权测试：玩家调用他人视图/写接口应 403；玩家响应中不得出现完整 `gameState`。
- 服务端生成视图与 AC-13 测试；旧版本 409、非法状态 422；重连后补齐到最新版本。
- WebSocket 断线→轮询降级→恢复推送。
- 主持令牌哈希校验与恢复码测试。

## 重评触发

- 需要多实例/高并发 → Redis adapter + PostgreSQL。
- 需要跨设备身份 → 引入账号或一次性绑定码。
- 实时性要求提升或 Socket.IO 协议限制成为问题。
