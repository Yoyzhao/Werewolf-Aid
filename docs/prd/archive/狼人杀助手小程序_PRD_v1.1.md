## 1. 产品概述

### 1.1 背景与要解决的问题

狼人杀是强流程、强信息的社交推理游戏，线下组局存在三个典型痛点：

1. **主持门槛高**：面杀需要一位懂规则、能记住夜间顺序、会判定胜负的「上帝」。新手不会主持，导致组局困难。
2. **规则记忆负担**：板子、角色技能、行动顺序、冲突判定（如同守同救）容易记错，争议频发。
3. **玩家缺乏私人辅助**：玩家需在不暴露身份的前提下查看技能提示、记录场上信息、获得策略建议；线下又难以把这些信息汇总给每个玩家。

### 1.2 产品定位

一款面向**线下狼人杀场景**的微信小程序：用一台手机即可让**完全不会玩的人**按引导主持完整对局并自动给出结果；每位玩家可通过**配对码**加入同一局，在自己手机上看身份、记标签、取攻略、获得 AI 建议，且**只看到自己该看的信息**。

### 1.3 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| **新手主持人**（首要） | 不会玩狼人杀，被推举主持 | 一步步照做就能完成整局，不判断、不记忆、不出错 |
| **联机玩家** | 每人一部手机，线下同桌 | 配对即加入，自动拿到自己的身份与公开进度，无需反复传递手机 |
| **独立玩家** | 只想自己记录、不加入房间 | 不配对也能独立使用个人助手，数据留在自己手机 |
| **进阶玩家** | 追求策略提升 | 用标签/发言要点沉淀信息，让 AI 基于这些信息给出建议 |

### 1.4 核心价值

- **零门槛主持**：把「懂规则」转化为「照着点」，主持人无需任何先验知识。
- **联机协同与保密兼顾**：进度自动同步，身份按角色权限下发——玩家只看到自己有权知道的信息。
- **自动裁定**：胜负、冲突、平票等由系统自动判定，减少争议。
- **信息沉淀 + 智能辅助**：玩家的标签与发言要点成为 AI 分析的上下文，建议有据可依。

### 1.5 已确认的关键决策

| 决策项 | 结论 | 对产品的影响 |
| --- | --- | --- |
| 使用形态 | 线下为主，主持人单机控场；玩家经**配对码**加入，也可独立使用 | 主持人端 + 玩家端两类视图，共享同一局数据 |
| 数据存储 | **云端同步，不保留历史** | 对局结束即清除云端数据；玩家私有记录留本机 |
| 信息保密 | **按角色权限下发**，未公开信息不同步给无权玩家 | 需建立信息可见性矩阵（见 5.5） |
| 板子口径 | **主流默认**：预女猎守、预女猎白，均屠边 | 按 12 人标准配置实现（见 6） |
| AI 范围 | 初版接入；**BYOK**，玩家自配 URL / Key / 模型名 | 采用云函数中转，兼容 Chat Completions（见 5.4、9.2） |
| AI 调用路径 | **云函数中转**，Key 不落库 | 绕开小程序合法域名限制；请求不持久化 |

## 2. 范围界定

### 2.1 初版（v1.1）包含

- 规则与攻略查阅：板子列表、角色图鉴、流程规则、术语表、搜索。
- 面杀主持辅助：开局设置 → **双模式发牌（接力查看 / 线下逐步确认）** → 夜间引导 → 白天引导 → 自动判定 → 结算复盘。
- **配对码联机**：主持人建房间、玩家配对加入并绑定编号、进度与身份同步、信息按权限下发、断线重连。
- 个人对局助手：身份标记、**玩家标签 / 信息记录 / 发言要点**、身份专属攻略提示、**独立（不加入）模式**。
- AI 辅助分析：基于局势 + 玩家标签/笔记的分析与建议；**玩家自配模型**经云函数中转。
- 板子：预女猎守（12 人）、预女猎白（12 人）。

### 2.2 初版不包含（明确排除）

- 账号体系、用户昵称系统、跨对局历史查询（云数据对局结束即清除）。
- 在线匹配、陌生人房间、语音房间；仅限线下同桌、主持人控场场景。
- 更多扩展板子（机械狼通灵师、新月等）与自定义板子编辑。
- 支付、社交分享、社区内容、语音播报、动画演出。

### 2.3 优先级定义

- **P0**：初版必须交付，缺失则产品不成立。
- **P1**：初版应尽量交付，可在 v1.x 补齐。
- **P2**：后续迭代，初版仅预留结构。

## 3. 用户与核心场景

### 场景 A：新手主持一场「联机」面杀局（核心场景）

> 小李被朋友推举当「上帝」，但他从没玩过。他打开小程序 → 选「预女猎守」→ 生成配对码并公布 → 12 位朋友扫码/输入配对码，各自在手机上绑定主持人当面告知的编号 → 小李选「线下发牌」，按屏幕步骤逐个确认「1 号是预言家、2 号是平民……」，每人只收到自己的身份；或使用「接力查看」让手机逐人传递。之后小李点「天黑请闭眼」，每晚按提示唤醒角色并记录动作；预言家、女巫在自己的手机上收到**仅本人可见**的查验/被刀信息。天亮后按提示完成竞选、发言、投票，系统自动判定胜负并揭晓全部身份。小李全程不需理解规则，玩家也不用来回传手机。

### 场景 B：玩家用标签沉淀信息，辅助 AI 决策

> 小王绑定为 5 号、拿到预言家。他在个人助手里给每位玩家打标签：「3 号 悍跳嫌疑」「7 号 金水」「2 号 发言划水」，并记下发言要点。局势陷入僵局时，他点「AI 分析」——系统把他的身份、当前存活情况、标签与笔记作为上下文，经他自配的模型给出「局势判断 / 可疑对象 / 下一步验人建议」，并标注依据。

### 场景 C：玩家选择不加入，独立记录

> 小赵不想配对（怕暴露或只想自己玩），直接在个人助手里标记身份、记标签与笔记，数据只存在自己手机，AI 分析同样可用，只是没有联机进度同步。

### 场景 D：临场查规则

> 玩家对「同守同救是否死亡」有争议，打开规则查阅 → 搜索 → 查看判定说明。

## 5. 功能需求详述

### 5.1 模块一：规则与攻略查阅

**设计原则**：内容内置于小程序（不依赖网络），面向临场快速查找，大白话优先。

| 功能点 | 需求描述 | 优先级 |
| --- | --- | --- |
| 板子列表 | 展示预女猎守、预女猎白的人数、角色构成、胜负口径；点击进入详情 | P0 |
| 角色图鉴 | 按阵营分类；每角色含技能、限制、常见打法、易错点 | P0 |
| 流程规则 | 分「一夜的流程」「一天的流程」「怎么算赢」三段，配顺序编号 | P0 |
| 术语表 | 词条 + 一句话解释，按拼音/首字索引 | P1 |
| 搜索 | 输入关键词，跨角色名、规则条目、术语匹配，结果分类展示 | P1 |
| 内容来源标识 | 每页底部注明「依据《狼人杀规则说明》整理，规则以开局约定为准」 | P1 |

### 5.2 模块二：面杀主持辅助（核心）

**设计原则**：主持人**零知识依赖**。系统只呈现「当前这一步该做什么」，用动词短句和大按钮；所有规则判断由系统完成。

#### 5.2.1 开局设置

- 选择板子：预女猎守 / 预女猎白（P0）。
- 设置玩家数量：默认按板子人数（12 人），可调（P1）。
- 录入玩家编号：1～N 号；可填昵称（P1，不填则显示编号）。
- 选择发牌模式：接力查看 / 线下逐步确认（P0，见 5.2.2）。
- 生成**配对码**并公布（P0，见 5.3）。
- 设置项（默认值，可改）：
  - 首夜女巫可否自救：默认**可自救**（面杀主流），可切换（P1）。
  - 是否开启警长竞选：默认**开启**（P1）。
  - 遗言规则：首夜有遗言、白天死亡有遗言、其余夜晚无（P0，按默认执行；可配置 P2）。

#### 5.2.2 双模式发牌

**模式 A：接力查看（沿用 v1.0）**

| 步骤 | 界面行为 | 说明 |
| --- | --- | --- |
| 1 | 全屏遮罩："请把手机交给 1 号玩家，其他人请勿观看" | 防止旁人看到 |
| 2 | 玩家点击「查看我的身份」 | 显示身份牌：身份名 + 一句话技能说明 + 阵营色 |
| 3 | 玩家点击「我已记住，交给下一位」 | 回到遮罩，进入下一位 |
| 4 | 重复至全部玩家 | 系统内部记录「编号 → 身份」映射 |
| 5 | 全部完成 | 提示："身份已发完，可以天黑请闭眼" |

**模式 B：线下逐步确认（新增）**——主持人掌控节奏，不传递手机

| 步骤 | 界面行为 | 说明 |
| --- | --- | --- |
| 1 | 屏幕显示："请 1 号玩家确认身份"，全屏身份牌 | 仅主持人持机，当面展示/告知 1 号 |
| 2 | 主持人确认玩家已知晓后点击「1 号已确认」 | 进入下一位 |
| 3 | 重复至全部玩家 | |
| 4 | 全部完成 | 提示进入夜晚 |

- 两种模式在**联机下均可用**：玩家若已绑定编号，其本人手机会在发牌完成后收到**仅自己的身份**（模式 B 下由主持人确认时同步下发）。
- **约束**：主持人设备即「上帝」，可见全局身份；查验/被刀等私密信息按 5.5 的权限矩阵下发。

#### 5.2.3 夜间流程引导

- 系统按板子的**固定行动顺序**逐步推进，每步一张大卡片：**角色名 + 大白话动作 + 操作区**。
- 预女猎守顺序：守卫 → 狼人 → 预言家 → 女巫。
- 预女猎白顺序：狼人 → 预言家 → 女巫（白痴无夜间行动）。

| 角色 | 主持人操作 | 系统自动处理 |
| --- | --- | --- |
| 守卫 | 点击被守护玩家编号（或空守） | 记录守护对象；校验不可连续两夜守同一人 |
| 狼人 | 点击击杀目标编号（可空刀/自刀） | 记录刀口；多狼统一由主持人代录 |
| 预言家 | 点击查验对象编号 | 内部查身份 → **仅查验者本人**收到结果（见 5.5）；若查验者未联机，仅在主持人端显示 |
| 女巫 | 获知「今晚 X 被刀」；选择用解药 / 毒药 / 不用 | 校验药瓶；执行**同守同救判定**；「今晚被刀者」仅女巫本人可见 |
| 猎人/白痴 | 无夜间行动，仅结算时判定技能 | 自动处理开枪/翻牌 |

- 夜晚结束：系统计算死亡名单（含平安夜），进入白天并同步公开信息。

#### 5.2.4 白天流程引导

1. **公布死讯**：显示「昨夜 X 号出局」或「平安夜」；若有死者，提示留遗言（首夜/按配置）。
2. **警长竞选（首日，可关）**：报名 → 依次发言 → 退水 → 警下投票 → 得票最多者当选；平票进入 PK 复投，再平则本局无警长；提供「狼人自爆吞警徽」操作入口。
3. **发言**：按警长指定顺序或死左/死右顺序逐个提示；支持「狼人自爆」打断（P1）。
4. **投票放逐**：主持人录入每票或点选归票对象 → 系统统计；平票进 PK + 复投，再平则本轮无人出局（P0）；警长票按 1.5 计（P0）。
5. **放逐后结算**：触发白痴翻牌免死、猎人开枪、狼王开枪等技能（按板子），系统提示选择目标。
6. **判定胜负**：进入 5.2.5。

#### 5.2.5 自动判定与冲突处理

| 情形 | 判定 |
| --- | --- |
| 所有狼人阵营出局 | 好人胜利 |
| 所有神职出局，或所有平民出局（屠边） | 狼人胜利 |
| 同守同救 | 目标玩家死亡 |
| 女巫同夜用两瓶药 | 系统拦截，仅允许一瓶 |
| 守卫连续两夜守同一人 | 系统拦截并提示 |
| 平票 | 进入 PK 流程；再平按规则处理 |
| 猎人/狼王死亡 | 按死亡方式判断是否可开枪（被毒/殉情不可） |

#### 5.2.6 结算与复盘

- 显示胜利阵营与原因（如「狼人胜利：神职全部出局」）。
- 揭晓全部身份：编号 → 身份 → 阵营（此时对所有已加入玩家公开）。
- 关键事件时间线：逐夜记录刀口、守护、查验、用药、放逐、自爆等（P1）。
- 提供「再来一局」（沿用玩家编号，重新生成配对码）与「返回首页」。
- **结算后触发云端数据清除**（见 8.2）。

#### 5.2.7 中断续局（P1）

- 每一步操作后同步当前对局状态；主持人重进小程序可从当前步骤恢复。

### 5.3 模块三：配对码联机

**设计原则**：配对即以「编号」为身份锚点；**绑定需主持人确认**，防止冒领他人身份；信息按权限下发。

#### 5.3.1 创建与加入

| 步骤 | 主持人端 | 玩家端 |
| --- | --- | --- |
| 1 | 开局设置完成后生成**配对码**（建议 6 位数字，限时有效） | — |
| 2 | 公布配对码（口播/展示二维码） | 输入配对码加入房间 |
| 3 | — | 输入主持人当面告知的**玩家编号**，提交绑定申请 |
| 4 | 房间列表显示「编号 X 申请加入」，主持人**确认** | 等待确认 |
| 5 | 确认后，该编号状态置为「已绑定」 | 收到自己的身份（若已发牌）与当前公开进度 |
| 6 | 全部绑定完成或开局 | 进入对局视图 |

- **防冒领**：同一编号只能绑定一次；主持人可「解绑/重置」某人（P1）。
- **独立模式**：玩家可选择「不加入房间，自己记录」，此时不接收任何联机数据，记录完全存本机（P0）。

#### 5.3.2 进度与身份同步

- 同步内容：当前阶段（夜/日/投票）、存活玩家、公开事件（死讯、放逐、警长）、**按权限下发的私密信息**（见 5.5）。
- 同步时机：主持人每次操作后即时推送；玩家端拉取当前快照。
- 一致性：以主持人端为**唯一数据源（_single source of truth_）**，玩家端只读自己的视图。

#### 5.3.3 断线重连（P1）

- 玩家切后台/网络抖动后重连，凭本地房间令牌恢复视图；期间错过的操作以最新快照补发。

### 5.4 模块四：个人对局助手

**设计原则**：每人一部手机；联机时身份由房间下发，独立模式下自行录入；玩家记录结构化，供 AI 使用。

| 功能点 | 需求描述 | 优先级 |
| --- | --- | --- |
| 身份标记 | 联机玩家自动显示自己的身份；独立玩家自行从角色列表选择，显示技能卡与阵营 | P0 |
| 玩家标签 | 对每位玩家（1～N）打标签，如「金水 / 查杀 / 悍跳嫌疑 / 划水 / 疑似狼」，可自定义文字标签 | P0 |
| 信息记录 | 针对每位玩家写自由文本信息记录 | P0 |
| 发言要点 | 按轮次记录各玩家发言要点（如「第 2 轮：3 号指责 7 号但逻辑矛盾」） | P0 |
| 身份攻略提示 | 按自身身份展示「玩法要点」「注意事项」「常见误区」，内容来自规则文档 | P0 |
| 私人笔记 | 自由文本，本地保存 | P1 |
| 清空/新建记录 | 一键重置当前记录 | P1 |
| 独立模式 | 不配对也能使用全部记录与 AI 功能 | P0 |

> 标签/信息记录/发言要点以「玩家编号 → 标签数组 + 文本」结构化存储，作为 AI 上下文（见 5.6）。

### 5.5 信息可见性矩阵（保密核心）

**原则**：玩家只能看到**其角色有权知道**的信息；系统按下表过滤下发。主持人端（上帝）可见全部。

| 信息项 | 主持人 | 玩家（已绑定编号） | 说明 |
| --- | --- | --- | --- |
| 自己的身份 | ✅ 全局可见 | ✅ 仅本人 | 绑定后下发 |
| 他人身份 | ✅ | ❌ | 永不向无权玩家下发 |
| 狼队友身份 | ✅ | ⚠️ 仅狼人玩家可见（规则内互认） | 见 12.1 待确认 |
| 预言家查验结果 | ✅ | ✅ 仅查验者本人 | 查验者未联机则仅主持人端可见 |
| 女巫「今晚被刀者」 | ✅ | ✅ 仅女巫本人 | 用药决策信息 |
| 夜间刀口 / 守护对象 | ✅ | ❌ | 非角色权限信息 |
| 死亡 / 放逐 / 警长 / 轮次 / 投票结果 | ✅ | ✅ 全员 | 公开信息 |
| 白狼王自爆、猎人开枪等触发结果 | ✅ | ✅ 全员 | 公开事件 |

> 该矩阵是「暂未公开信息不能同步给玩家」的落地规则，开发时须按角色权限在服务端（云函数）过滤，而非仅在前端隐藏。

### 5.6 模块五：AI 辅助分析（BYOK + 云函数中转）

**设计原则**：AI 输出**建议而非结论**，必须给出依据并提示可能出错；模型由玩家自备。

#### 5.6.1 模型配置（玩家自配）

| 字段 | 说明 |
| --- | --- |
| API Base URL | 玩家自定义的兼容 Chat Completions 端点，如 `https://api.example.com/v1/chat/completions` |
| API Key | 玩家自有密钥 |
| 模型名称 | 如 `gpt-4o-mini` 或玩家使用的其他模型 |

- 配置保存在**玩家本机**（建议加密存储）；云函数仅在调用时接收，**不落库、不持久化**。
- 协议：兼容 OpenAI **Chat Completions** 请求/响应格式（用户表述的 "chat compact" 按此理解，见 12.1）。
- 调用链：玩家端组装上下文 → 云函数 → 云函数向玩家配置 URL 发起 HTTPS 请求 → 结果回传玩家端。

#### 5.6.2 上下文组装

AI 输入由以下部分自动组装（玩家可编辑）：

1. **我的身份**（联机下发或自行录入）。
2. **当前局势**：轮次、存活玩家编号、公开事件（来自联机进度）。
3. **玩家标签与信息记录**（来自 5.4）。
4. **发言要点**（来自 5.4）。
5. **自由描述框**：玩家补充。

#### 5.6.3 输出与约束

| 功能点 | 需求描述 | 优先级 |
| --- | --- | --- |
| 分析输出 | 分三段：①局势判断 ②可疑对象与理由 ③下一步行动建议 | P0 |
| 依据可追溯 | 输出中标注「基于你标记的 X 标签 / Y 发言」 | P1 |
| 边界提示 | 每次输出固定展示："AI 分析仅供参考，可能出错，请自行判断" | P0 |
| 失败兜底 | Key 无效 / 额度不足 / 网络异常时给出友好文案，不阻断其他功能 | P0 |
| 输入安全 | 提示词约束模型不输出违规内容；对自由文本做基础过滤 | P1 |
| 合规提示 | 玩家使用自配模型，需自行确认服务合规性与数据流向 | P1 |

## 7. 核心流程与状态机

```
[首页]
 ├─ 规则与攻略查阅 → 板子/角色/流程/术语 → 返回
 ├─ 面杀主持辅助（主持人端）
 │    └─ 开局设置(生成配对码) → 玩家配对绑定 → 双模式发牌 → 对局循环：
 │         夜 → 记录夜间动作(私密信息按权限下发) → 日(死讯→[警长·首日]→发言→投票→技能结算)
 │              → 判定胜负？ ─否→ 下一夜
 │                          └是→ 结算复盘 → 清云数据 → 再来一局/返回
 ├─ 配对加入（玩家端）
 │    └─ 输入配对码 → 绑定编号 → 主持人确认 → 收到身份+公开进度
 │         → 个人助手(标签/记录/发言要点) → AI 分析 → 返回
 └─ 独立模式（玩家端）→ 自行录身份 → 个人助手 → AI 分析 → 返回
```

**对局状态枚举（主持辅助）**：`SETUP → PAIR → DEAL → NIGHT → DAY_SHERIFF → DAY_SPEECH → DAY_VOTE → SETTLE → RESULT`。

## 9. 技术方案约束

### 9.1 小程序形态

- 微信原生小程序（WXML/WXSS/JS）+ **微信云开发**（云数据库/云函数/实时推送）。
- 静态规则内容内置；对局状态走云端同步；个人记录与 AI 配置留本机。
- 目标：可在微信开发者工具编译、真机预览，并支持托管发布流程。

### 9.2 AI 接入：BYOK + 云函数中转

- **BYOK（Bring Your Own Key）**：模型 URL / Key / 名称由玩家配置，降低平台成本与备案负担。
- **云函数中转**：玩家端 → 云函数 → 玩家配置的 Chat Completions 端点。作用：
  1. 绕开小程序「合法域名」限制（云函数的 HTTP 请求不受此限）。
  2. Key 仅在请求中使用，不写日志、不落库。
- **前端 JS 处理**：上下文组装、请求发起、结果解析在小程序 JS 层完成；云函数只做转发。
- **关于「微信平台自带的发送」**：若后续希望提供无需自配模型的默认选项，可接入微信平台自带的 AI 能力作为备选通道；v1.1 以玩家自配为唯一通道（见 12.1 待确认）。

### 9.3 待定项（列入 12）

| 待定项 | 说明 |
| --- | --- |
| 云开发环境 | 开通云开发；确认免费额度/计费与并发 |
| 实时同步方案 | 云数据库实时推送 / 云函数 + 轮询，按体验与成本选择 |
| 配对码策略 | 位数、有效期、防暴力试探（限频） |
| 合规 | 玩家自配模型的内容责任边界；小程序类目与审核要求 |

### 9.4 内容维护

- 规则与攻略内容以 `狼人杀规则说明.md` 为源，内置为本地数据；内容变更随小程序版本更新。

## 10. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 易用性 | 主持流程每一步不超过一个主要动作；文案为大白话；按钮文字明确 |
| 信息保密 | 服务端按 5.5 矩阵过滤；前端不得以「仅隐藏样式」方式保护私密信息 |
| 一致性 | 主持人端为唯一数据源；玩家端视图最终一致 |
| 容错 | 误操作可回退一步；发牌/绑定/投票需二次确认；断线可重连 |
| 性能 | 本地操作响应即时；同步延迟可接受范围待定；AI 请求需 loading 与超时提示 |
| 隐私 | 云数据对局结束即删；Key 不上传、不落库；提示玩家勿填真实姓名等敏感信息 |
| 可访问性 | 文字对比度足够；按钮触控区不小于 44px |
| 兼容性 | 主流微信版本；不同屏幕尺寸适配 |

## 13. 验收标准

| 编号 | 验收条件 |
| --- | --- |
| AC-1 | 从未玩过狼人杀的测试者，仅按界面提示，可独立完成一场 12 人预女猎守对局并得到正确胜负结果 |
| AC-2 | 双模式发牌均可用；接力查看时非当前玩家身份不展示且查看后回遮罩；线下逐步确认按编号逐个推进 |
| AC-3 | 系统能正确执行同守同救、女巫同夜限一瓶、守卫不可连守、警长 1.5 票、平票 PK |
| AC-4 | 预女猎守与预女猎白两个板子的夜间顺序、角色技能、胜负判定与规则文档一致 |
| AC-5 | 主持人建房间生成配对码，玩家可配对、绑定编号并经主持人确认加入；进度与身份同步 |
| AC-6 | **信息可见性符合 5.5 矩阵**：玩家看不到他人身份、查验结果仅查验者可见、被刀信息仅女巫可见；服务端过滤有效（前端隐藏不算通过） |
| AC-7 | 玩家可选择不加入房间独立使用个人助手，数据仅存本机 |
| AC-8 | 玩家可给每位玩家打标签、记录信息与发言要点，切换页面后保留；这些内容被组装进 AI 上下文 |
| AC-9 | 玩家配置自配 URL/Key/模型名后，AI 经云函数返回「局势判断 / 可疑对象 / 行动建议」三段内容，并显示边界提示；Key 不在云端落库 |
| AC-10 | AI 请求失败（Key 无效/额度不足/无网络）时有兜底文案，不影响其他功能 |
| AC-11 | 对局结算后云端房间与对局数据被清除，无历史留存 |
