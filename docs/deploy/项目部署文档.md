# 项目部署文档（P0）

- 版本：v1.0（2026-11-26）
- 适用范围：M1 v1.3.1 P0（单机主持闭环 + 助手 + AI 中转 + 规则页）
- 部署形态：**Node 单进程**（Fastify 同源提供静态 SPA + `/api`），不使用 Nginx/Docker
- 关联：[技术架构](../tech/tech-arch.md)、[ADR-005](../tech/arch/ADR-005-部署与运行形态.md)、[开发环境](../tech/dev-info.md)、[T-024 演练证据](../test/evidence/M1/T-024/verification.md)

## 1. 拓扑与端口

```text
浏览器 ──HTTPS/443──> Node/Fastify
                        ├── /             apps/web/dist（@fastify/static）
                        ├── /api/v1/*     Fastify 会话/AI 中转
                        └── 出站 HTTPS    AI 供应商（用户自配端点）
HTTP/80 ──301──> HTTPS/443（Node 内置跳转，或由云 LB 承担）
```

| 端口 | 用途 | 说明 |
| --- | --- | --- |
| 443 | HTTPS（Node 直连） | systemd `CAP_NET_BIND_SERVICE` 授权 |
| 80 | HTTP→HTTPS 301 | `HTTP_REDIRECT_PORT=80`；云 LB 模式设为 0 |
| 3000 | 云 LB 回源 | `HTTPS_ENABLED=0`、`TRUST_PROXY=1` |

- 单实例运行；P1 的 WebSocket/SQLite 在 M2 启用，P0 不启动。
- HTTP/1.1，不启用 HTTP/2（为 M2 Socket.IO 兼容保留）。

## 2. 服务器目录布局

## 3. 首次部署

### 3.1 系统准备

```bash
# Node 24（示例：NodeSource 或官方二进制）
node -v   # 必须 >= 24
npm -v

useradd --system --home /opt/werewolf-aid --shell /usr/sbin/nologin werewolf
install -d -o werewolf -g werewolf /opt/werewolf-aid/releases
install -d -o root -g werewolf -m 750 /etc/werewolf-aid /etc/werewolf-aid/tls
install -d -o werewolf -g werewolf /var/log/werewolf-aid
```

- 防火墙/安全组：放行 80、443；出站放行 443（AI 供应商）。
- 时区：系统使用 UTC；应用展示按 Asia/Shanghai，无需改系统时区。

### 3.2 发布目录与构建

```bash
TS=$(date -u +%Y%m%dT%H%M%S)
REL=/opt/werewolf-aid/releases/$TS
sudo -u werewolf mkdir -p "$REL"

# 方式 A（推荐）：CI/本地构建后上传源码与构建产物
rsync -a --exclude .git --exclude .artifacts --exclude node_modules ./ "$REL"/

# 方式 B：服务器构建（需要 devDependencies）
cd "$REL"
sudo -u werewolf npm ci
sudo -u werewolf npm run build
sudo -u werewolf npm prune --omit=dev
```

产物检查：

```bash
test -f apps/web/dist/index.html
test -f apps/api/dist/server.js
```

### 3.3 环境变量

```bash
sudo cp docs/deploy/env.production.example /etc/werewolf-aid/env
sudo sed -i "s|replace-with-openssl-rand-hex-32|$(openssl rand -hex 32)|" /etc/werewolf-aid/env
sudo chown root:werewolf /etc/werewolf-aid/env
sudo chmod 640 /etc/werewolf-aid/env
```

必须核对：

- `PUBLIC_ORIGIN` 与浏览器实际地址完全一致（协议、域名、端口）。
- `WEB_DIST_DIR=/opt/werewolf-aid/current/apps/web/dist`。
- Node 直连：`HTTPS_ENABLED=1`、`PORT=443`、证书路径正确。
- 云 LB 回源：`HTTPS_ENABLED=0`、`PORT=3000`、`TRUST_PROXY=1`，由 LB 设置 HSTS。

### 3.4 TLS 证书

推荐 **DNS-01**（Node 占用 80/443，避免 certbot standalone 冲突）：

```bash
# 示例：Cloudflare 插件
certbot certonly --dns-cloudflare \
  --dns-cloudflare-credentials /etc/letsencrypt/cloudflare.ini \
  -d werewolf.example.com

install -o root -g werewolf -m 640 /etc/letsencrypt/live/werewolf.example.com/fullchain.pem /etc/werewolf-aid/tls/fullchain.pem
install -o root -g werewolf -m 600 /etc/letsencrypt/live/werewolf.example.com/privkey.pem /etc/werewolf-aid/tls/privkey.pem
```

若必须用 webroot：先 `systemctl stop werewolf-aid`（或临时 `HTTP_REDIRECT_PORT=0` 并重启），再执行
`certbot certonly --webroot -w /var/www/certbot -d <域名>`，完成后恢复服务。Node 不代理 ACME 挑战，因此不推荐 webroot。

续期：

```bash
# 部署钩子：复制证书后重启（Node 只在启动时读取证书）
cat >/etc/letsencrypt/renewal-hooks/deploy/werewolf-aid.sh <<'SH'
#!/bin/sh
DOMAIN=werewolf.example.com
install -o root -g werewolf -m 640 /etc/letsencrypt/live/$DOMAIN/fullchain.pem /etc/werewolf-aid/tls/fullchain.pem
install -o root -g werewolf -m 600 /etc/letsencrypt/live/$DOMAIN/privkey.pem /etc/werewolf-aid/tls/privkey.pem
systemctl restart werewolf-aid
SH
chmod +x /etc/letsencrypt/renewal-hooks/deploy/werewolf-aid.sh

systemctl list-timers | grep certbot
certbot renew --dry-run
```

### 3.5 进程守护

```bash
sudo cp docs/deploy/werewolf-aid.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo ln -sfn "$REL" /opt/werewolf-aid/current
sudo systemctl enable --now werewolf-aid
sudo systemctl status werewolf-aid --no-pager
```

查看日志：

```bash
journalctl -u werewolf-aid -f
```

日志为 pino JSON；已脱敏 Cookie 与 CSRF 头，AI Key/上下文不写日志。

## 4. 发布、回滚与备份

### 4.1 发布（原子切换）

```bash
# 新目录准备并自检后
sudo ln -sfn /opt/werewolf-aid/releases/<新版本> /opt/werewolf-aid/current
sudo systemctl restart werewolf-aid
curl -fsS https://<域名>/api/v1/health
```

- 保留最近 3 个 release；旧目录确认稳定后再删除。
- 切换后必须重启：进程启动时读取环境变量与证书。

### 4.2 回滚

```bash
sudo ln -sfn /opt/werewolf-aid/releases/<上一版本> /opt/werewolf-aid/current
sudo systemctl restart werewolf-aid
curl -fsS https://<域名>/api/v1/health
```

- 静态与后端在同一 release 内，一次切换同时回滚。
- 仅静态回滚：将 `WEB_DIST_DIR` 指向上一版本 `apps/web/dist` 并重启（不推荐长期保留双路径）。
- 本地演练已验证：release A → B（页面出现 B 标记）→ 回滚 A（标记消失）→ 健康检查 200；后端 `apps/api/dist` 从备份恢复后健康检查 200。见 [T-024 演练记录](../test/evidence/M1/T-024/verification.md)。

### 4.3 备份与恢复（P0）

P0 无数据库，服务端不持久化对局；备份对象为**配置、证书与发布目录**：

```bash
sudo tar czf /var/backups/werewolf-aid-$(date -u +%Y%m%d).tar.gz \
  /etc/werewolf-aid /opt/werewolf-aid/current
```

恢复：

```bash
sudo systemctl stop werewolf-aid
sudo tar xzf /var/backups/werewolf-aid-<日期>.tar.gz -C /
sudo systemctl start werewolf-aid
curl -fsS https://<域名>/api/v1/health
```

P1 启用 SQLite 后：使用 `sqlite3 data/lrs.sqlite ".backup '<目标>'"`，并演练 WAL 检查点恢复；不在 P0 范围。

## 5. 预发布冒烟

部署后在服务器或任意可访问机器执行：

```bash
node scripts/deploy/smoke.mjs https://<域名>
# Node 直连且启用 80 跳转时追加：
node scripts/deploy/smoke.mjs https://<域名> --redirect http://<域名>
```

检查项（22 项）：首页 HTML/SPA 挂载、CSP、`X-Content-Type-Options`、HSTS、缓存策略、健康检查、会话与 CSRF、Cookie `HttpOnly/SameSite/Secure`、AI 中转未授权 401、API JSON 404、SPA fallback、静态资源长缓存与 gzip、HTTP→HTTPS 301 且保留路径。

预期输出：`SUMMARY 22/22 passed`。

## 7. 已知限制与待办

- 真实服务器/域名/证书未提供，T-024 仅完成本地 HTTPS 演练与部署资产；真实 443、证书签发、ICP 需在拿到服务器后执行。
- 云 LB 场景 HSTS 由 LB 设置；Node 在 `HTTPS_ENABLED=0` 时不发送 HSTS。
- P1 WebSocket/SQLite 未启用；M2 部署时需补充 SQLite 备份与 WS 压测。
- Node 直接终止 TLS 时证书续期需要重启进程（当前实现），后续可评估热加载。
