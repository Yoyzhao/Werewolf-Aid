## T-047 P1 部署扩展

### 目标与边界

**目标**：在 P0 单进程部署基础上启用 SQLite 持久化与 WebSocket，并补齐备份/恢复与压测记录。

**范围内**：
- SQLite 文件持久目录、WAL、启动/发布迁移、权限。
- 备份：`sqlite3 .backup` + WAL 检查点；恢复演练；保留策略。
- Node HTTPS 下的 WSS；`/ws` 与静态/API 路由隔离；WS 消息上限与连接数限制。
- 部署文档更新（环境变量、目录、迁移、备份、回滚、监控）。
- 10 房间 / 130 连接压测与日志观测；健康检查仍为 `/api/v1/health`。

**范围外**：多实例/Redis/粘性会话（M3+）。

### 验证与验收

- 真实/预发布环境完成部署、迁移、备份恢复与 WSS 冒烟。
- 压测达到单实例目标；异常时有日志与降级。
- 产出：更新后的部署文档与 P1 部署记录；证据：`docs/test/evidence/M2/T-047/verification.md`。

### 风险与恢复

- `better-sqlite3` 原生构建：T-036 已首日验证；部署机仍失败则切 `node:sqlite` 并回归。
- SQLite 单实例：不横向扩展；增长前迁 PostgreSQL（ADR-002）。
- WS 断线：客户端重连 + 轮询降级，服务端不保证消息重放。
