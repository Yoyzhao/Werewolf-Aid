## T-013 移动端原型

### 目标与边界

**目标**：用可点击原型确认 P0 主持端与助手的页面结构、主流程和移动端交互，作为 5B 细化与 5C 实现的基线。

**范围内**：首页、开局设置、发牌 A/B、夜间、首日竞选、死讯/发言/投票、结算、个人助手、规则查阅；360/430 两档主视图，320 兼容检查。

**范围外**：视觉精修、真实数据、后端接口、P1 联机。

### 技术方案

- 输出单文件 HTML/CSS 可交互原型，放在 `docs/prototype/`；不接后端、不实现规则。
- 主持端单列步骤卡；主按钮固定底部拇指区；1–12 号大网格；模式 B 默认遮罩 + 二次揭示。
- 深色高对比；安全区/100dvh；无横向滚动；触控 ≥44px；输入框 ≥16px。
- 页面清单：首页、设置、发牌 A、发牌 B、夜间卡、竞选、死讯/发言、投票、结算、助手、规则。

### 实施步骤

1. 按 360px 画主持主流程线框；补 430px 检查。
2. 画发牌 A/B 与夜间角色卡，标注口播与私密信息。
3. 画助手/标签/发言要点/局势/AI 结果页。
4. 输出可点击原型与页面清单，标注对应 PRD 章节/AC。

### 验证与验收

- 用户在 360/430 手机视口走完主持主流程与助手记录；320px 抽查不横向滚动。
- 主持主操作单手可达；模式 B 有遮罩/二次揭示；私密信息默认隐藏。
- 产出：`docs/prototype/` 原型与页面清单；证据：用户验收记录。

### 风险与恢复

- 页面过多导致原型失焦：先主持闭环，规则/助手可简版。
- 设计未覆盖异常态：5B 补 loading/空态/失败/无权限/重复提交。
