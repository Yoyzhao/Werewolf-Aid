## T-014 交互细化与契约冻结

### 目标与边界

**目标**：把 5A 原型细化为可实现的状态与交互，冻结 5C/5D 共享契约。

**范围内**：加载/空态/成功/失败/无权限/重复提交；发牌模式 B；Wake Lock fallback；AI loading/取消/超时/错误；本地存储失败；主持回退/二次确认；P1 房间契约只引用不实现。

**范围外**：代码实现、真实接口、P1 联机实现。

### 技术方案

- 每个关键页面列出状态表与交互分支，标注对应 AC。
- 与 [api-contract.md](../../../tech/api-contract.md) 对齐 AI 中转、会话/CSRF、错误码；P1 契约仅保留引用。
- 冻结：页面结构、导航、组件映射、文案、移动端布局规则、AI 状态机。
- 输出原型 v2 + 交互状态清单；重大偏差回写 PRD/架构并记录。

### 实施步骤

1. 逐页补状态表与异常分支。
2. 核对移动端约束（360/430/320、DPR、safe-area、键盘）。
3. 核对 AI/本地存储/网络失败与降级文案。
4. 用户验收并冻结 5C/5D 输入。

### 验证与验收

- 状态表覆盖 PRD 7.4 的全部列；每个 P0 AC 有对应交互路径。
- 原型 v2 可点击；5C/5D 可按冻结契约开工。
- 产出：原型 v2、状态清单、契约引用；证据：用户验收记录。

### 依赖与风险

- **依赖**：T-013、T-025 两套原型完成。
- 状态遗漏导致实现返工：以 PRD 7.4 为清单逐项打勾。
- 契约未冻结：T-015/T-019 不得进入实现，先回 5B。
